How it works

What happens when you press Scan.

Six steps, from looking to putting things back, plus an honest list of what Dustpan built and what it borrowed. Each step has a plain explanation. If you write code, open the developer notes.

Developer notes are folded away. Open any one, or switch to show them all.

The short version

Think of a careful cleaner with a checklist.

A checklist

= 179 rules

It only looks in places on the list, and each place comes with a note saying what's there.

Locked rooms

= the protected list

iCloud, Mail, Photos, Keychains and app databases. Never touched, whatever the checklist says.

A box by the door

= the Trash

Nothing gets thrown out. It goes into the box, and you can take it back out.

A receipt

= History

Every move is written down: what, from where, and how big. That's how "Put back" knows where things go.

The whole trip

Six steps. You're in charge of step five.

  1. 1LookOnly where the rules point.
  2. 2MatchPick the one rule that fits best.
  3. 3ProtectDrop anything off-limits.
  4. 4MeasureReal space on disk, counted once.
  5. 5ChooseSafe items pre-ticked. You decide.
  6. 6TrashMoved, logged, can be put back.

Steps 1 to 4 only read. Nothing on your Mac changes until you press the button in step 5.

1

Look only where the rules point.

Dustpan doesn't rummage through your whole Mac. It has a list of 179 known places where apps keep things they can make again: caches, logs, build files, old installers.

It visits those places and nothing else. Your Documents folder isn't on the list, so the Junk scan never looks there.

Without Full Disk Access, macOS keeps some places closed. Dustpan skips them and tells you which ones, instead of guessing.

Developer notes
  • Rules live in Core/Rules/rules.json: paths (with ~ and wildcards), optional globs, risk, minAgeDays, why (checked at load: not empty, at most 140 characters).
  • JunkScanner (an actor, off the main thread) expands each path into rule roots. Roots that resolve through a symlink, or outside the home folder, are refused. Candidates that are symlinks are skipped, never followed.
  • Rules marked needsFullDiskAccess don't run without it; they're returned as skipped so the UI can name them.

2

When two rules fit, the closest one wins.

Some places are covered by more than one rule. Homebrew's downloads sit inside the general Caches folder, for example. Dustpan picks the most specific rule, because it knows the most about that folder.

One exception beats everything: "Never" rules. These mark things like your Ollama models or Spotify downloads. If a Never rule covers a place, it disappears from the scan, even if another rule says it's a cache.

Developer notes

Precedence when two rules claim the same path:

  1. .never wins, and anything inside a .never path is dropped.
  2. The deeper root wins (~/Library/Caches/Homebrew beats ~/Library/Caches/*).
  3. The more literal glob wins (*.ShipIt beats *).
  4. .review beats .safe.
  5. Then catalogue order.

3

Off-limits stays off-limits.

After matching, every item is checked against a do-not-touch list. Anything inside one of these places, or holding one, is dropped. A rule can't override it.

There's one more check you'd never think of: if a folder holds an app's database file, the whole folder is left alone. Apps like note-takers keep your actual data that way, and it can look like a cache from the outside.

This list is also checked a second time, right before anything moves.

Developer notes
  • ProtectedList is checked by the scanners and by Cleaner. An item is dropped if it is in a protected root or contains one (moving ~/Library would move ~/Library/Mail).
  • Roots include /System, /usr, ~/Library/Mobile Documents, ~/Library/Mail, ~/Pictures/*.photoslibrary, ~/Library/Keychains, Apple containers and group containers.
  • The database check runs during the size walk: a .sqlite, .realm or .db file outside Caches and the Trash drops the whole item.

4

Measure the space it really takes.

A file's "size" and the space it uses on your disk aren't always the same. Dustpan counts the space on disk, because that's what you get back.

When one found folder sits inside another, its bytes are counted once, not twice. And it notes the date of the newest file inside each item, which matters in the next step.

Developer notes
  • Size is .totalFileAllocatedSizeKey summed over regular files; symlinks count 0 and aren't followed.
  • When one item lies inside another, the outer item's walk leaves the inner one out (excludedURLs), so no byte is counted twice.
  • modified is the newest file inside the item, not the folder's own date.
  • Formatted with ByteCountFormatter(.file): decimal units, as Finder shows them.

5

You choose. Dustpan only suggests.

Every item shows its size, its age and a one-line reason from its rule. Some come already ticked, but only if they pass every question on the right.

"Review" items are never ticked for you: they're usually fine to remove, but worth a look. Items an open app is using wait until you quit that app.

Nothing moves until you press Move to Trash.

Developer notes
  • isSelected = risk == .safe && newest file ≥ 7 days old && !detectionOnly.
  • A rule's own minAgeDays filters earlier: items younger than that aren't listed at all.
  • Rules with requiresQuit check NSRunningApplication; the row shows a "Quit … first" pill and can't be ticked while the app runs.

6

Into the Trash, onto the receipt.

Dustpan uses the same Trash as Finder. Open the Trash in your Dock and you'll see everything it moved.

Each move is written into Dustpan's History, so Put back knows where every item came from.

The only way anything is deleted for good is Empty Trash, and Dustpan asks first and shows you the size.

Developer notes
  • Cleaner is the only type that touches files. It calls FileManager.trashItem(at:resultingItemURL:) and re-checks ProtectedList and symlinks first.
  • Each move becomes a CleanupLog row in SQLite (via GRDB) in ~/Library/Application Support/Dustpan/.
  • emptyTrash(_:) is the single permanent delete, and only takes the summary the user confirmed.

The other tools

Same careful idea, different jobs.

Duplicates

Looks in Downloads, Documents, Desktop and Pictures for files with identical contents. Comparing every file in full would be slow, so it narrows down in stages:

  1. Same size? Different sizes can't match.
  2. Same first 16 KB?
  3. Same last 16 KB?
  4. Same fingerprint of the whole file?
  5. Duplicates. Keeps the copy in the most deliberate place.
Developer notes

Fingerprints are XXH3 hashes (xxHash), the whole file streamed in 1 MB reads. Skips links, packages, tool folders (node_modules, .git…), hidden files, protected places and iCloud files that aren't downloaded. Keeper order: Documents, Desktop, elsewhere, Downloads; then the oldest.

Apps & leftovers

When you remove an app, Dustpan looks in your Library for files it left behind, and says how sure it is about each one.

High
Medium
Low

A file named exactly after the app's ID (like com.figma.Desktop) is a strong match. A file that just contains the app's name is a weaker one. Strong and medium matches are ticked for you; weak ones aren't.

Developer notes

LeftoverMatcher reasons: bundleID, bundleIDPrefix, teamID (group containers), nameToken (whole words), each with a MatchConfidence. The app and its leftovers go to the Trash through Cleaner, logged like everything else.

Space map

Draws your disk as rectangles: the bigger the folder, the bigger the box. You can click into any box and keep going down.

Developer notes

SizeTree stores millions of files as flat arrays (names, sizes, parent, firstChild, nextSibling), never one object per file. The top items come from a Heap (swift-collections). The layout is a squarified treemap adapted from MacDirStat.

Large & old

Lists big files in your home folder that haven't been opened or changed for a while. Nothing is ticked for you; it's a list to look through.

Developer notes

LargeOldFinder asks Spotlight (MDQuery on kMDItemFSSize, kMDItemLastUsedDate) and walks the same scope to catch what Spotlight doesn't index. Skips ~/Library, the Trash, protected places, packages and tool folders. Age is the later of last opened and last modified.

Words on this page

A tiny glossary.

Cache
A copy an app keeps so it doesn't have to download or work something out again. Deleting it is safe; the app just rebuilds it, a little slower the first time.
Full Disk Access
A macOS permission that lets an app see protected folders like the Trash. Without it, Dustpan still works but sees less, and says so.
Trash vs delete
Moving to the Trash is a step you can undo. Deleting is not. Dustpan only deletes when you empty the Trash yourself.
Fingerprint (hash)
A short code worked out from a file's contents. Two files with the same contents get the same code, so comparing codes is a fast way to spot duplicates.
Space on disk
The room a file actually takes up. Disks store data in small blocks, so even a tiny file uses at least one whole block.
Open-source licence
The terms an author sets for reusing their work. MIT, BSD and Apache allow it, as long as you keep their credit and licence text, which Dustpan does.
